### 다음 작업의 순서와 완료 조건

1. 기존 PTS manifest의 sample ID·frame index·PTS·time base·원본 해시를 단일 이미지
   어댑터 출력과 연결한다. 정지 이미지용 null 시각을 실제 영상의 시각으로 추측해 채우지 않는다.

   후보·해 없음·오류를 모두 남기고 실행하지 못한 프레임도 별도 집계한다.
3. 설정·가중치 해시와 raw 출력·원본 오버레이를 보관하고 후보 반환 비율, 오류 원인,

   평가는 각각 실제 실행 기록이 생긴 뒤 완료로 바꾼다.

다음 작업은 E1용 manifest 결합 및 100장 실행이다. TVCalib/E2/독립 라벨/앱 채택은
미실행이다. 아래 내용은 2026-09-10의 준비 단계 인계 기록으로 보존하며, 그 당시
`not_run`/CPU/DNS 제약을 현재 E0 상태로 해석하지 않는다.

## 1. 유지할 결정

제품의 기본 흐름은 `수동 기준점 입력 → 정합`이 아니라 `자동 관측 → 자동 정합 후보 → 품질 검사 → 필요한 구간만 검수`다.

기존 P0의 PTS 인덱스, 원본 프레임 공급, 캐시, 편집기, 오버레이, 이력은 유지한다. 수동 입력은 평가 자료 작성, 오류 분석, 선택적 보정에 사용하되 모든 분석 프레임에 요구하지 않는다. 수동 점·선 입력 확장이나 독자적인 혼합 정합 엔진, 큰 관측 DB 개편을 자동 모델 실행의 선행 조건으로 두지 않는다.

다음 투자 대상은 공개 자동 엔진의 재현과 비교다. 아직 우리 영상에서의 정확도 우열이 확인되지 않았으므로 특정 엔진을 제품 엔진으로 확정한 결정은 아니다.

| 순서 | 후보 | 다음 실행에서 먼저 확인할 것 |

이 표는 실행 준비 순서이지 정확도 순위가 아니다. PnLCalib refinement on/off는 같은 detector를 사용하는 ablation으로 기록한다. TVCalib를 포함한 서로 다른 엔진의 일치도 독립 정답을 대신하지 않는다.

Sportlight 공식 README의 24GB GPU 안내만으로 RTX 3070에서의 추론을 불가능하다고 판정하지 않는다. 반대로 8GB 실행을 검증 없이 보장하지도 않는다. 코드·가중치·데이터의 사용 조건 검토는 각각 남아 있으며, 이번 문서화로 upstream 자료를 복사하거나 재배포하지 않는다.

## 5. 해석상의 핵심 위험

**인지 오류와 경기장 모델 불일치를 분리한다.** PnLCalib의 고정한 추론 예제는 105×68 경기장, 반지름 9.15의 중앙 원 등 표준 축구장 구조를 사용한다. 유소년·풋살·복합 마킹 영상에서 그 모델에 맞는 행렬이 반환되더라도 실제 경기장 위치가 확인된 것은 아니다. 길이·너비만 줄여도 내부 마킹의 비율과 형태가 맞아지는 것은 아니다. 근거 코드는 [실험 계획의 1차 자료](README.md#10-1차-자료)에 연결되어 있다.

**추론 입력과 평가 정답을 분리한다.** 추론에는 수동 점·선·박스·ROI 프롬프트를 제공하지 않는다. 평가용 독립 마킹은 모델 출력을 보기 전에 고정하고 추론 프로세스에 전달하지 않는다. 모델 예측을 검증점으로 복사하거나 내부 적합 손실이 낮다는 이유만으로 `usable`을 부여하지 않는다.

**결과 종류를 분리한다.** 환경 실패·OOM·미실행·해 없음·후보 생성·독립 검증 통과를 각각 기록한다. 미실행을 모델 정확도 0점으로 만들지 않고, 실패 프레임을 성공률의 분모에서 몰래 제외하지 않는다. 한 영상에서 얻은 결과는 다른 경기장이나 휴대폰에 대한 일반화 보장이 아니다.

## 6. 다음 작업: PnLCalib 공개 예제와 원본 좌표 어댑터

### E0 — 재현 가능한 첫 추론

1. `candidates.json`의 PnLCalib upstream SHA로 별도 작업 복사본을 만들고, 앱과 분리된 환경을 사용한다. 코드·가중치 사용 조건 및 파일 해시를 기록한다.
2. 공개 예제 또는 사용 조건을 확인한 방송 축구 이미지에서 실제 가중치를 로드해 추론한다. 이 단계의 실패를 휴대폰 도메인 실패로 분류하지 않는다.
3. 사용자 장비에서 RTX 3070을 사용할 때는 batch=1, 한 엔진씩 시작하고 장치·dtype·로드 시간·추론시간·메모리를 측정한다. OOM이나 CPU 대체 실행은 별도 설정으로 기록한다.
4. 오버레이뿐 아니라 raw keypoint/line 예측, camera/H, no-solution과 오류를 sidecar로 저장한다. 파일별 sample ID, 원본 PTS, 전처리 변환, 엔진·가중치·설정 해시를 연결한다.
5. 출력 방향·단위·원점과 resize/crop의 역변환을 검증한다. 원본→모델 변환과 경기장 변환을 혼동하지 않고, 왜곡을 포함하는 카메라 모델을 근거 없이 3×3 H로 축약하지 않는다.

**E0 완료 조건:** 실제 가중치 로드 및 공개 예제 추론 로그, 원본 좌표 오버레이와 raw-output sidecar, 좌표 변환 검증 기록, 수동 프롬프트 0회, 환경·가중치·설정 식별 정보가 모두 남아 있어야 한다. 파일 다운로드나 그럴듯한 오버레이만으로 완료 처리하지 않는다. E0 통과는 공개 예제 실행의 확인이지 실제 경기 정확도 검증이 아니다.

### E1 — 고정된 100장 비교

E0를 통과한 PnLCalib를 준비된 동일 100장에 적용한다. refinement on/off 결과를 별도 run으로 기록하고, 다음으로 TVCalib의 predicted-segmentation 경로를 같은 입력에 적용한다. 독립 라벨이 없으면 실행률·후보 반환 현황만 보고하고 정합 정확도는 `not_measured`로 둔다. 평가 프로토콜·허용 오차·분모는 [실험 계획](README.md#8-평가와-정답)을 따른다.

### E2 및 후속 투자

시간축 평가는 정의한 4개 구간을 실제로 추출·추론한 뒤 수행한다. 단일 프레임 인지 실패면 대상 도메인 적응, 필드 구조 불일치면 모델·라벨 대응, 시간 단절이면 자동 전파·재초기화를 검토한다. 실측 실패 원인을 확인하기 전 수동 선 입력기나 큰 DB 개편으로 돌아가지 않는다. P1의 영상 좌표 기반 선수 등장 구간 검색은 이 비교 완료를 선행 조건으로 두지 않는다.

## 7. 인계 시 지킬 범위

기존 기록의 CPU 전용 환경과 DNS·바이너리 다운로드 실패는 당시 실행의 제약이다. 새 실행 장비에서 다시 확인하며 모델 자체의 실패나 RTX 3070 OOM 결과로 해석하지 않는다.

현재 앱의 `status != usable → coordinate_level=image` 규칙은 그대로 유지한다. 자동 후보는 실험 sidecar에 격리하고 앱의 수동 저장·검증 경로를 우회하지 않는다. 원본·식별 가능한 프레임·가중치·로컬 세션·실험 결과를 공개 Git/CI에 넣지 않는다. 필요한 독립 평가 자료도 로컬에 둔다.

이 문서 변경은 실행 현황과 다음 작업의 문서화다. 가중치 다운로드, 모델 추론, 앱 통합 또는 PR 병합을 수행한 변경으로 해석하지 않는다.
