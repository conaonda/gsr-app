# GSR · 휴대폰 영상 정합 진단기

GSR의 원본 영상 정합 편집기. 휴대폰 축구 영상의 프레임을 실제 경기장 대응점에 맞추고, **적합에 쓰지 않은 독립 검증점**으로 결과를 검수하는 로컬 앱입니다. 원본 파일은 외부로 전송하지 않습니다.

v0.2 첫 개발 묶음은 좌표 사용 자격 보완, 저장 없는 정합 미리보기, 원본 편집·오버레이입니다. 후속 개선으로 풋살장 기준도, 이름으로 기준점 연결, 빠른 프레임 탐색과 캐시가 추가됐습니다. 선·원호 정합과 선수 추적은 후속 단계입니다.

현재 구현 반영 상태, 실제 영상에서 확인한 병목, v0.2 잔여 작업, v0.3 관측 계약과 P1 선수 추적의 다음 순서는 [docs/development-status.md](docs/development-status.md)에 정리되어 있습니다.

## 실행

Python 3.11 이상과 PATH에 등록된 FFmpeg/FFprobe가 필요합니다.

```powershell
cd gsr-app
python -m pip install -r requirements.txt
.\run.ps1
```

브라우저에서 http://127.0.0.1:8765 를 엽니다.

세션은 프로젝트의 `.gsr/sessions.sqlite3`에 저장됩니다. 다른 저장소를 쓰려면 실행 전에 `GSR_DB_PATH` 환경 변수로 SQLite 경로를 지정합니다. 원본 영상은 복사하지 않으며 원래 위치에 유지해야 합니다.

## 작업 순서

1. 로컬 영상의 절대 경로를 입력합니다. 우선 2~3분 구간으로 시작하세요.
2. 기준 프레임을 선택합니다. 시각은 원본 PTS와 time base로 관리합니다.
3. 원본을 휠로 확대하고 화면 이동 도구로 위치를 조정합니다. 화면 맞춤과 1:1 보기로 돌아갈 수 있습니다. 화면 확대는 저장할 원본 좌표를 변경하지 않습니다.
4. 기준점 추가 도구로 영상의 지면 기준점을 클릭한 뒤, 풋살장 기준도에서 같은 위치를 클릭하거나 코너·중앙선 교차점·중심점을 이름으로 선택하고 연결합니다. 적합점은 최소 네 개가 필요하며 넓게 분포해야 합니다. 선택 도구로 점을 이동하거나 방향키로 미세 조정하고, 실행 취소·다시 실행으로 복원합니다.
5. 정합 미리보기를 실행하고 원본 위 경기장 선을 보며 수정합니다. 미리보기는 저장 이력을 만들지 않습니다. 점·역할·치수를 수정하면 이전 계산 결과는 현재 초안에 적용되지 않습니다.
6. 적합에 사용하지 않을 별도의 검증점을 지정합니다. 검증 입력 중에는 예측 오버레이를 숨겨 관측을 보조합니다. 검증점이 없으면 계속 검토 필요 상태이며 공간 분석에는 영상 좌표만 허용됩니다.
7. 검토한 결과를 저장합니다. 치수를 모르면 정규화 좌표를 사용하며, 미터 좌표에는 사용 가능한 정합과 확인된 치수·근거가 모두 필요합니다. 프레임별 초안은 현재 브라우저 세션에서 복원되며, 새로고침이나 종료 전에 필요한 결과를 저장하세요.
8. 근접 프레임으로 전파한 결과는 다시 독립 검증합니다. 팬·줌·가림·렌즈 전환에서는 재고정이 필요할 수 있습니다. 저장 이력에서 당시 입력을 다시 열거나 JSON으로 진단 결과를 내보냅니다.

## 범위와 한계

- 수동 대응점 기반 정합, 보수적인 시간 전파, 독립 검증, 프레임별 품질 이력과 SQLite 저장이 대상입니다.
- 사용 가능 판정은 관측 지점에서의 진단이며 영상 전체나 다른 프레임의 정확도를 보증하지 않습니다. 관측되지 않은 구간은 미평가입니다.
- 경기장 그림은 대응점 입력 도구입니다. 실제로 존재하는 지면 선·교차점만 선택해야 합니다. 공중의 공이나 선수 몸은 기준점으로 사용하지 않습니다.
- 기준도의 점선 원·페널티 영역·골대는 규격 미확인 참고 그림입니다. 네 개의 분명한 기준점이 안 보이면 다른 프레임에서 시작해야 하며, 현재는 선·원호만으로 정합하지 않습니다.
- P1 선수 검출·추적·정체성 검수, P2 사건·구역 검색, P3 SAM2·자연어 검색은 후속 단계입니다.
- 실제 사용자 영상의 정합 정확도와 처리 성능은 해당 영상을 입력한 뒤 평가해야 합니다.
- 원본 PTS가 명확한 영상은 빠르게 탐색하고, 본 프레임은 메모리 캐시로 재사용합니다. PTS가 불명확하거나 탐색에 실패하면 순차 디코딩하므로 긴 영상에서는 느릴 수 있습니다. 최초 등록은 전체 프레임을 분석하지만, 변경 없는 영상의 재등록은 저장된 인덱스를 재사용합니다.
- 한 번의 시간 전파는 최대 30프레임입니다. 자동 추적한 기준점은 검증점으로 재사용하지 않습니다.
- 기본 적합·독립 검증 오차 기준은 5픽셀입니다. 이는 개발용 진단 기준으로, 실제 경기 영상에서 보장된 정확도 기준은 아닙니다.
- 기존 저장 결과가 검토 필요 상태인데 경기장 좌표 자격을 갖고 있다면, 조회 시 영상 좌표로 제한하고 정정 근거를 함께 반환합니다. SQLite의 과거 분석 내용은 덮어쓰지 않습니다.

## 검증

```powershell
python -m pytest -q
node --test tests/editor-core.test.cjs
node --check web/app.js
```

실행 중인 서버까지 검사하려면 다음을 실행합니다. 합성 테스트 데이터와 진단 이력이 생성되므로 별도의 `GSR_DB_PATH`로 실행한 서버를 사용하세요.

```powershell
$env:GSR_TEST_URL='http://127.0.0.1:8765'
python -m pytest tests/test_acceptance.py -q
```

전체 검사를 한 번에 실행하려면 다음을 사용합니다. 임시 SQLite·합성 영상·독립 서버를 사용하므로 사용자 세션을 변경하지 않습니다. GitHub Actions도 같은 명령을 사용합니다.

```powershell
python -m pip install playwright
python -m playwright install chromium
python tests/run_checks.py
```

브라우저가 없는 환경에서는 `python tests/run_checks.py --skip-browser`로 기하·API·편집 코어 검사를 실행할 수 있습니다. `tests/browser_smoke.py`는 실제 캔버스 클릭, 미리보기, 초안 복원, 비동기 응답 처리를 검사합니다.

API/모듈 계약은 [CONTRACT.md](CONTRACT.md)에 있습니다.

실제 영상의 대기 시간과 픽셀 일치를 재현하려면 `python tests/benchmark_video.py "영상의 절대 경로" --check-pixels --screenshots`를 실행합니다. 원본과 정상 세션은 바꾸지 않으며 결과는 Git에서 제외된 `data/video-benchmark/`에 남습니다. [개선 계획과 측정 결과](docs/improvement-plan.md)를 참고하세요.
